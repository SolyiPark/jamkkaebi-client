## 발견한 문제와 수정

### 다른 친구 조회 실패 시 이전 전시 잔류

`ExhibitionVisitSession.Begin`이 이전 친구의 Scene을 유지해 새 친구 조회가 실패하면 이전 전시와 그 친구의 보상·선물 조작이 남을 수 있었다. 요청 소유자가 바뀌면 Scene을 제거하도록 수정했다. 같은 친구의 재시도에서는 기존 Scene을 유지한다. 요청 세대 번호를 통한 늦은 응답 차단은 유지했다.

EditMode 회귀 테스트와 실제 Player에서 7×7 친구 → 20×20 친구 전환 검사를 추가했다. 오류 화면에서 기존 객체가 사라지고 방문 보상·선물 버튼이 비활성화되는 것을 확인했다.

### 공유 인증 갱신 취소 시 잘못된 결과 사용

갱신 소유 코루틴이 취소되면 대기 요청이 null이나 이전 갱신의 성공 응답을 사용할 수 있었다. 갱신 시작 시 기본 실패 결과를 새로 지정하도록 수정했다. 취소 후 대기 요청은 예외 대신 `AUTH_REFRESH_INTERRUPTED`를 반환한다.

실제 서버가 반환한 만료 응답으로 두 요청을 갱신 대기 상태에 두고 소유 요청을 취소하는 회귀 테스트를 추가했다. 해당 검사는 reissue HTTP를 시작하기 전에 취소하여 서버의 회전 토큰을 소비하지 않는다. HTTP 송신 후 취소·연결 단절의 서버 처리 완료 여부는 보장할 수 없다.

## 출시·후속 연결 범위

미구현 범위는 기능 결함과 구분한다. 현재 더미 자산에 실제 보유 ID를 임의로 넣거나 홈 자동 저장을 활성화하지 않았다. 보유 ID와 로컬 자산 매핑, 공통 인증 세션·로그인 화면·OAuth 복귀 처리, 자신의 저장 전시를 홈에 복원하는 흐름, 격자 규격 합의가 남아 있다. 친구 전시의 실제 아트는 placeholder 상태이다. 링크 공유·QR과 모바일 실기기·배포 서버 검증도 남아 있다.

서버에 버전/ETag 계약이 없어 GET~PUT 사이 다중 기기 동시 편집의 손실은 완전히 방지할 수 없다. 테스트는 기본 20×20 서버에서 저장·공개 스냅샷 갱신을 검증했으며, 클라이언트 7×7 방문 화면은 호환되는 고정 스냅샷으로 검증했다. 실제 서버와 홈의 규격을 합의하기 전까지 20×20 스냅샷을 7×7 화면에 축소하거나 일부만 표시하지 않는다.

사용자 작업으로 남아 있던 `AGENTS.md` 수정은 이번 기능 커밋에 포함하지 않는다. 로그·빌드·검증용 토큰 파일·Unity 자동 변경 설정도 커밋하지 않는다.

## PR #7 리뷰 후속 검증

CodeRabbit의 요청 핸들 수명 지적을 확인해 수정했다. `ReloadServer`·`LookupServer` 같은 중첩 코루틴이 `_socialRequest`나 `_serverBusy`를 해제하지 않으며, `RunSocialRequest`가 상태 변경·목록 갱신·결과 알림까지 소유권을 유지한 뒤 정리한다. 재접속은 이 최상위 코루틴을 취소한다. 잘못된 null 클라이언트는 기존 요청을 취소하기 전에 거부한다.

Player에 상태 변경 후 재접속 시 이전 요청 알림이 남지 않는 검사와 인증 실패 후 유효한 재접속이 서버 요청 목록을 복원하는 검사를 추가했다. `Logs/ServerContract/Run-20261011-190424/`에서 EditMode 103개와 Player 244개, 실제 HTTP 검증·GPU 종료 검사가 통과했다. XML 문서 주석 부족 경고에 대응해 동작·취소·실패 계약과 테스트 시나리오를 문서화했다. 원격에서 별도로 추가된 주석 커밋도 병합해 보존한다.
