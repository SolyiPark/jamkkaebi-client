# 친구 탭 프론트엔드 구현

기존 친구 탭의 `Friends.unity`를 「잠깨비 친구 탭.pdf」의 여섯 화면으로 교체했다. 친구 관계와 전시 방문 흐름은 로컬 샘플 데이터로 동작한다. 계정, 게임 재화, 보상, 서버 저장에는 아직 연결하지 않는다.

## 화면과 조작

| PDF 페이지 | 구현 | 확인할 조작 |
| --- | --- | --- |
| 1 | 친구 목록, 내 코드, 일일 보상 현황 | 프로필을 눌러 전시 방문, 상자 선물, 코드 복사, 차단 목록 열기 |
| 2 | 받은 요청과 보낸 요청 | 수락, 거절, 보낸 요청 취소, 목록 수 갱신 |
| 3 | 오늘의 추천 3명과 시대별 복원 표시 | 친구 요청, 이미 보낸 요청 비활성 표시 |
| 4 | 코드로 추가하는 하단 시트 | 8자리 영문·숫자 조회, 검색 결과, 중복 요청 방지 |
| 5 | 친구 전시 미리보기 | 도깨비·건물 선택, 선택 정보, 방문 보상, 선물, 차단 확인 |
| 6 | 차단 목록 | 해제 확인, 해제 후 친구 관계 미복구 |

PDF의 종이색 배경, 초록색 버튼, 사각 아바타, 구분선과 여백을 uGUI로 구성했다. 공통 셸의 하단 탭은 그대로 사용한다. 작은 화면에서는 세로로 스크롤하여 하단 조작을 확인한다.

전시는 모의 스냅샷 패키지의 임시 도형 객체를 재현한다. 기본 패키지는 도깨비 3개와 건물 2개다. 미설계 객체의 프리팹이나 실제 친구의 홈 배치를 확정하는 구현이 아니다. 객체 선택은 상세 설명을 변경하고 배치 편집은 제공하지 않는다. [스냅샷 기능 통합 보고서](friends-snapshot-integration.md)에 조회·이동·예외 처리와 검토 방법을 기록한다.

## 실행과 검토

Unity 6000.3.23f1에서 `Assets/Jamkkaebi/Scenes/UIPrototype.unity`를 열고 Play한 뒤 하단 **친구** 탭을 선택한다. `Friends.unity`는 Additive 콘텐츠 씬이므로 공통 셸을 통해 실행한다. 이미 씬 연결을 저장했으므로 초기 이관 도구를 재실행할 필요가 없다.

1. 친구 12명, 받은 요청 3개, 보낸 요청 2개가 표시되는지 확인한다.
2. 요청함에서 받은 요청을 수락하면 친구 수가 늘고 요청 수가 줄어든다.
3. 코드로 추가에서 `G2RY-4ABC`를 조회하고 요청을 보낸다. `H2RX-9KTA`는 기존 친구라 추가 요청이 비활성화된다. 자신의 코드와 차단된 코드는 조회할 수 없다.
4. 달항아리의 프로필을 눌러 전시를 방문하고, 도깨비와 건물을 선택해 상세 문구를 확인한다.
5. 방문 보상은 하루 전체 친구를 합쳐 한 번, 선물도 하루 한 명으로 제한된다. 수막새는 받기 가득 상태다. 다른 친구로 전환해도 일일 제한은 유지된다.
6. 차단 해제 뒤 해당 사용자가 친구 목록에 자동 복구되지 않는지 확인한다.
7. 세로 드래그는 목록을 스크롤하고 가로 드래그는 기존 하단 탭 사이를 전환한다. 친구 탭을 떠났다가 돌아와도 로컬 상태와 화면을 유지한다.

상태는 이번 Play 세션의 메모리에만 저장한다. 재실행하면 샘플 초기값으로 돌아간다. 자정 초기화는 기기의 로컬 날짜를 사용한다. 실제 서비스에서는 서버 시각과 서버의 보상 판정으로 교체해야 한다. 요청 만료와 추천 갱신 문구는 디자인을 재현하는 샘플이며 실제 14일 만료 스케줄과 새 추천 생성은 연결하지 않았다.

**코드 복사**는 실제 클립보드에 복사한다. **링크 공유**와 **QR 코드**는 초대 URL과 플랫폼 공유 계약이 정해지기 전까지 준비 상태 안내를 표시한다. 받은 선물을 홈에서 개봉하는 기능은 이 작업의 범위에 포함하지 않는다.

## 코드 구조와 후속 연결

- `Assets/Jamkkaebi/Scripts/UI/Friends/FriendsPresenter.cs`: 화면 생성, 입력과 로컬 상태 표시.
- `Assets/Jamkkaebi/Scripts/UI/Friends/FriendsPreviewState.cs`: 샘플 친구·요청·추천·차단, 일일 방문·선물 상태.
- `Assets/Jamkkaebi/Scripts/UI/Friends/FriendProfile.cs`: 화면 검토에 필요한 프로필과 복원 통계.
- `Assets/Jamkkaebi/Scenes/Friends.unity`: 기존 씬 GUID, 카메라와 루트를 보존하고 프론트엔드 컴포넌트를 연결.
- `Assets/Jamkkaebi/Editor/FriendsSetup.cs`: 저장된 기존 더미 씬만 변경하는 일회성 batch 이관 도구. 일반 실행과 빌드에서는 사용하지 않는다.

런타임 Canvas는 `MirrorSceneRoot` 아래에서 전용 카메라를 사용한다. 생성 오브젝트는 친구 씬과 레이어 11을 따른다. EventSystem과 AudioListener를 추가하지 않는다. 세로·가로 제스처 처리는 기존 `CollectionScrollRect`를 재사용하며, 도감 데이터에는 의존하지 않는다. 공통 `MirrorInput`, 탭 순서와 빌드 씬 목록을 변경하지 않았다.

백엔드 연결 시에는 프리뷰 상태를 서버 응답 기반 상태로 교체하고, 각 명령에 비동기 처리·로딩·실패 복구를 추가해야 한다. 화면 모델을 서버 DTO로 간주하면 안 된다. 친구 전시는 별도 버전의 스냅샷, 안정적인 객체 ID, 프리팹 대응표, 좌표·각성·레벨 계약을 확정한 뒤 현재 임시 도형을 실제 재현기로 교체한다. 이번 변경에는 서버 호출이나 미확인 엔드포인트를 추가하지 않았다.

최초 프론트엔드의 실행 검증과 화면 캡처는 `friends-validation.md`, 후속 스냅샷 모의 기능 통합 결과는 `friends-snapshot-integration.md`에 기록한다.
