# 도감 화면 검증 기록

검증일: 2026-10-09. Unity **6000.3.23f1**, Windows x64 Development Player, 기본 D3D12 렌더링. 아래 결과는 확정 시트의 유물·시대와 전체 이미지 교체 슬롯을 반영한 후 실제 실행한 최종 결과다.

## 구현 범위

기존 `Collection.unity`의 더미 사각형·카운터를 시대 목록 → 시대 상세 → 유물 상세로 교체했다. 삼국·고려·조선 각 3종의 유물 정의와 5/9종의 복원 완료 샘플 기록을 사용한다. 수집률은 복원 완료한 유물 종류만 계산하며, 해당 시대의 모든 유물을 복원하면 건물이 해금된 것으로 표시한다. 신규 `N`은 상세를 처음 열면 해제된다.

유물·시대는 [「깨비별 특성」 시트1](https://docs.google.com/spreadsheets/d/1h2kPX9OrotI1mofpJxDIXg06z8RpFlT2e5LXNudL_rw/edit?gid=0)의 `A2:C10`을 그대로 반영했다. 삼국은 금동여래입상·금동대향로·금관, 고려는 석불·고려청자·나전칠기, 조선은 옥새·마패·묘작도다. `CollectionCatalogData`의 고정 정의와 `CollectionDemoData`의 완료 기록을 분리했다. `CollectionSetup.SyncCatalog`로 기존 자산을 갱신했으며 카탈로그 GUID는 `22828c1a012011741b19400997c6af8e`로 유지됐다.

작업대·발굴 어댑터와 실제 연결하지 않았다. 작업대 연결 API·ID·수명·저장 책임은 `collection-integration.md`에 기록했다. 정령 이름은 `정령 이름 미정`으로 표시하고 건물 이름·설명·복원 이야기는 임시 콘텐츠다. 그림은 새 목록에 맞춘 교체 가능한 벡터 대체 이미지다. 저장·서버·인벤토리·보유 수량·전시관 배치 연동은 구현 범위에 포함되지 않는다.

시대별 그림 슬롯 5개, 유물별 그림 슬롯 5개와 공통 UI 그림 슬롯 17개를 제공한다. 공통 설정은 `CollectionAppearance.asset`이며 씬 참조 GUID는 `49d8d7188a1f0144cbddcbf62b76986a`다. `CollectionSetup.ConfigureImages`는 현재 씬 계층을 유지하며 설정 참조만 연결했다. 이미지가 없으면 기존 벡터·단색 표시를 유지한다. 교체 순서와 적용 위치는 연결 계약 문서의 이미지 교체 안내에 기록했다.

```powershell

```

로그는 `Logs/Integration/EditMode.xml`, `editmode.log`, `build.log`와 `Logs/Integration/Player-20261009-174522/verification.txt`, `player.log`에 있다. 이미지 설정 연결 로그는 `Logs/Integration/collection-images-configure.log`다. Player가 종료한 뒤 GPU 버퍼 관련 오류 패턴까지 검사했다. `Logs/`와 `Builds/`는 생성물이며 커밋하지 않는다.

## 도감과 회귀 검사

- 중복 복원 완료는 수집 수·건물 수·신규 이벤트를 늘리지 않는다. 알 수 없는 종류 ID를 등록하지 않는다.
- 확정 시대·유물의 ID, 표시명, 시대 소속과 순서를 검사한다. 저장된 카탈로그 자산과 고정 정의 코드의 명칭·설명 일치도 검사한다. 폐기한 샘플 유물 6종은 조회·복원 등록을 거절한다.
- 임시 카탈로그에 시대·유물의 각 그림 슬롯 10개를 서로 다른 영속 Sprite로 저장한다. 순서·표시명을 변경하고 동기화한 뒤 재로드하여 ID별 Sprite GUID·localFileID와 카탈로그 GUID 보존, 확정 명칭·순서 복구를 검사했다. 운영 자산을 변경하지 않고 임시 자산은 정리했다.
- 실제 Player에 서로 다른 3색 Sprite와 공통 외형을 주입해 시대·유물·정령·건물·잠금 그림, 공통 UI 17개 슬롯과 실제 배경 렌더 픽셀을 검사했다. 썸네일·상세 분리, 유물별→시대별→공통 배경 순서, 빈 슬롯 대체, 9-slice, 원본 색상과 장식 Raycast 비활성화를 검사했다.
- 교체한 이미지 위에서도 시대·유물 카드가 공통 MirrorInput으로 열리고, 공통 외형 제거·재주입과 모든 임시 참조 복구 후 복원 종류·개수·신규 상태가 보존되는지 검사했다.
- 카탈로그를 저장하고 재로드한 경우에도 중복 시대/유물 ID와 존재하지 않는 시대 참조를 거절한다.
- 미복원 유물의 카드 클릭과 직접 상세 요청을 모두 차단한다.
- 상세 조회 후 신규 표시가 해제되고, 뒤로 가면 같은 시대 화면으로 돌아온다.
- 세로 드래그는 상세 본문을 스크롤하고 가로 카드 스와이프는 탭을 전환한다. 스와이프가 카드 클릭을 발생시키지 않는다.
- 도감 본문 맨 아래에서 친구 탭으로 이동했다 돌아와도 페이지와 스크롤 위치를 유지한다. 프로필 바 유무에 따라 숨김 탭의 뷰포트 높이가 바뀌는 경우를 포함한다.
- 빈 공유 기록으로 교체하면 이전 샘플에서 열었던 유물 상세를 닫고 잠금 상태를 표시한다. 원래 기록을 다시 연결하면 수집 정보를 복구한다.
- 더미 완료 등록 API로 잠긴 유물을 등록하면 카드와 통계가 갱신된다. 이 검사는 작업대 연동 완료를 의미하지 않는다.
- 공통 EventSystem/AudioListener, 탭 격리, 홈 하우징 길게 누르기·주변 메뉴, 작업대 타이머 일시정지·복귀·입력, 친구 전용 드래그의 기존 회귀 검사도 통과했다.

## 화면 확인

확정 데이터 반영 실행 `Player-20261009-171431/`에서 시대 표시·확정 명칭·유물 상세와 임시 정령 표시를 직접 확인했다. 이미지 슬롯 확장 실행 `Player-20261009-174522/`의 기본 화면 캡처도 생성됐다. 실제 원본 아트는 아직 연결하지 않았으므로 기본 벡터 화면을 유지하며, 임시 3색 Sprite 검사는 기본 캡처를 마친 뒤 실행했다.

최초 상태는 5/9·55%이고, 두 해상도 캡처 `Collection_Overview_480x1040.png`, `Collection_Overview_768x1024.png`는 통합 검사 중 더미 완료를 한 종류 추가한 **6/9·66%** 상태다. 넓은 세로 화면에서 본문이 뷰포트보다 길면 스크롤을 사용한다.

같은 날 초기 화면 구현 검증은 EditMode 60개·Player 156개(`Player-20261009-165930/`), 확정 데이터 반영 검증은 63개·162개(`Player-20261009-171431/`)였다. 당시 Noto CJK 글리프 잘림과 숨김 탭 리사이즈 후 스크롤 위치 문제를 수정했고, 이번 이미지 교체 실행에서도 해당 회귀 검사를 통과했다.

실제 Android/iOS 손가락 입력, 노치, 모바일 성능과 배포 빌드는 검증하지 않았다.
