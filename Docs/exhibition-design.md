# 홈 전시관 설계 기록

기록일: 2026-09-23. 사용자와 논의한 요구사항 및 후속 설계 기준이다. 사용자가 구현 착수를 지시했으며, 아래의 7×7 격자 기준을 후속 확정했다. 검증 결과는 `exhibition-validation.md`에 기록한다.

## 확정 요구사항

- 기존 홈 화면의 콘텐츠를 아이소메트릭 전시관으로 대체한다.
- 배경 원본 위치: 작업공간의 `잠깨비배경분리/제목_없는_아트워크-1 2.png`부터 `제목_없는_아트워크-10 2.png`까지. 현재 프로젝트 기준으로 상위 폴더에 있다. 모두 4320×7680이다.
- 1~10번을 레이어로 겹쳐 하나의 풍경을 구성한다. 숫자가 최종 합성 순서임을 단정하지 않는다. 질감 레이어의 합성 방식은 확인이 필요하다.
- 5번은 전시관 바닥이다. 후속 사용자 지시에 따라 상판의 각 변을 7등분한 7×7 논리 격자가 향후 하우징의 기준이다. 게임 화면에는 격자선을 표시하지 않는다.
- 홈·작업대·도감·친구 전체에 좌우 스와이프 탭 전환을 적용하고, 하단 탭 직접 터치도 허용한다. 전시관 내부의 여러 방을 넘기는 요구가 아니다.
- 원근감은 배경 레이어별 이동량 차이로 표현한다. 실제 확대·축소 조작은 추후 추가할 수 있도록 기반을 분리한다.
- 정령은 이번에 구현하지 않는다. 전시관·격자·표시 순서는 정령 코드에 의존하지 않아야 한다.
- 향후 건물 뒤를 지나는 정령이 가려질 수 있도록 깊이 정렬 기반을 마련한다.

## 논리 격자: 의미와 좌표 계약

사용자의 후속 지시: “상판을 기준으로 각 변을 7등분한 격자를 임의로 생성하여 논리 격자를 구성해둬. 실제 그림에 표시하지는 말고.”

따라서 원본의 미세한 선을 판독해 맞추려던 이전 계획을 대체한다. 상판 외곽을 기준으로 두 방향 모두 7칸, 총 49개의 논리 셀을 사용한다. 렌더링용 격자선은 만들지 않으며, 선택적인 에디터 Gizmo만 제공하고 기본값은 끈다.

기준 에셋: `Assets/MobileUI/Configuration/ExhibitionGrid.asset`. 전체 원본 캔버스를 자르지 않고 중앙 피벗, 1000 PPU로 임포트한다. 이미지 공간은 4.32×7.68 로컬 단위다. 상판의 후방 꼭짓점을 `O=(0, 0.675)`, 한 변의 끝점 차이를 `(2.1, -1.2)` 및 `(-2.1, -1.2)`로 잡는다. 따라서 `U=(0.3, -1.2/7)`, `V=(-0.3, -1.2/7)`이며, 전방 꼭짓점은 `(0, -1.725)`다. 대응 원본 픽셀(왼쪽 위 원점)은 후방 `(2160,3165)`, 우측 `(4260,4365)`, 좌측 `(60,4365)`, 전방 `(2160,5565)`다. 손으로 그린 외곽을 근사한 평행사변형이며, 필요 시 Inspector에서 조정할 수 있다.

### 기준 공간과 보정값

- 기준 공간은 연출 변형 전의 플랫폼 로컬 2D 공간이다. 화면 픽셀이나 탭 전환 중 위치를 저장 좌표로 쓰지 않는다.
- `O`: 기준 격자 교점인 원점.
- `U`, `V`: 상판의 두 격자 방향으로 각각 한 칸 이동하는 로컬 벡터. 방향과 칸 간격을 함께 나타낸다. 상판 외곽의 두 변을 각각 7등분한 벡터이며 임의의 30도 각도를 강제하지 않는다.
- 연속 격자 좌표 `(u, v)`를 플랫폼 좌표로 변환하는 식은 `P = O + uU + vV`다. 반대로는 독립적인 두 축으로 구성한 2×2 행렬의 역변환을 쓴다.
- 정수 교점 `(i, j)`와 셀을 구별한다. 기본 설계에서 셀 `(i, j)`의 중심은 `(i + 0.5, j + 0.5)`다. 셀 선택은 격자 좌표의 내림과 범위 검사로 처리한다. 실제 건물의 배치 앵커는 별도로 정의한다.
- 사용 가능한 상판 경계와 유효 셀 집합을 명시한다. 화면에 보이는 플랫폼 옆면이나 투명 여백은 배치 영역이 아니다. 범위 밖 입력을 가장자리 칸으로 임의 보정하지 않는다.
- 원본 이미지의 여백, Sprite 피벗, Pixels Per Unit, 자르기 여부를 보정 데이터와 함께 기록한다. 임포트 변경으로 이미지와 격자의 대응 관계가 깨지지 않아야 한다.

### 입력·배치·확장 분리

- 입력 변환 순서: 화면 터치 → 공통 뷰포트/RenderTexture 좌표 → 전시관 카메라 좌표 → 플랫폼의 현재 표시 변환을 역적용한 로컬 좌표 → 격자 좌표 → 유효 셀 판정.
- 기존 `MirrorInput`에서 이미 수행한 변환을 중복 적용하지 않는다. 확대·축소, 화면 비율, 탭 슬라이드, 플랫폼 연출이 달라져도 동일한 상판 위치는 동일한 셀로 판정되어야 한다.
- 향후 배치 데이터는 셀 좌표, 방향, 점유 셀 범위, 배치 앵커를 중심으로 구성한다. 화면상의 위치·줌 값·시차 오프셋은 하우징 배치 데이터에 저장하지 않는다.
- 플랫폼과 그 위 콘텐츠는 동일한 플랫폼 표시 변환을 공유한다. 배경 시차 연출 때문에 건물이나 정령이 바닥에서 미끄러지면 안 된다.
- 격자 변환, 유효 범위, 향후 점유 판정은 배경 합성·입력 인식·정령 AI와 분리한다. 정령 없는 상태에서도 독립적으로 사용·검증할 수 있어야 한다.
- 깊이 정렬은 바닥 접점/정렬 앵커를 기준으로 한다. 배경·플랫폼·배치물·앞쪽 장식의 큰 표시 구간과, 배치물 사이의 깊이 정렬을 구분한다.
- 큰 건물은 단일 스프라이트 정렬만으로 모든 가려짐을 해결하지 못할 수 있다. 앞면·지붕 등 표현 분리와 별도 정렬 앵커를 지원할 수 있도록 설계한다. 실제 분리는 건물 에셋 확보 후 판단한다.

### 향후 변경 시 유지할 기준

7×7 분할은 사용자 확정값이다. 상판 외곽 위치를 보정해도 칸 수를 임의로 바꾸지 않는다. 현재 유효 범위는 전체 49셀이고, 제외 셀을 데이터로 지정할 수 있다. 건물 점유·회전·배치 편집과 정령 이동은 향후 콘텐츠 구현 범위다. 정령 이동 가능 영역은 하우징 유효 영역과 별도의 규칙으로 확장할 수 있게 한다.

## 반드시 구분할 두 연출

사용자가 두 연출은 별개임을 명시했다. 같은 효과, 같은 재생 조건, 같은 완료 플래그로 묶지 않는다.

| 구분 | 최초 접속 등장 연출 | 홈 배경 원근감 연출 |
| --- | --- | --- |
| 목적 | 처음 풍경이 구성되어 나타나는 느낌 | 탭을 넘길 때 레이어 깊이 차이 표현 |
| 계기 | 게임 최초 접속 시 홈 표시 | 홈이 포함된 좌우 탭 전환 |
| 구동 기준 | 경과 시간과 레이어별 등장 지연 | 드래그/전환 진행량과 레이어별 시차 계수 |
| 변화 | 투명도·등장 위치 등 | 먼 배경은 작게, 가까운 배경은 크게 이동 |
| 반복 | 정해진 최초 재생 범위에서 한 번 | 최초 연출 완료 여부와 무관하게 매 전환에 반응 |
| 취소/정리 | 조작 개입 시 완성 상태로 정리하는 기본안 | 스와이프 취소 시 기준 상태로 복귀 |

- 최초 연출이 끝났다고 원근감 연출을 비활성화하면 안 된다. 탭 재방문으로 최초 연출을 재시작하면 안 된다.
- 재생 상태, 설정값, 제어 책임을 분리한다. 최종 표시값은 기본 배치, 최초 등장 오프셋, 전환 시차, 확대·축소를 명시적인 순서로 합성해 서로 덮어쓰지 않도록 한다.
- 하단 버튼으로 홈에 진입·이탈할 때도 공통 전환 진행량으로 원근감을 구동하는 설계안이다. 사용자에게 제시한 계획이며 스와이프와 같은 전환 경로를 사용한다.
- 최초 재생 범위는 앞선 보고에서 “앱 실행 후 홈 첫 표시마다 한 번”으로 해석했다. 사용자 원문은 “처음 게임 접속 시에만”이며 설치/계정 생애 최초 1회인지에 대한 별도 확답은 없다. 이 해석을 확정된 영구 저장 요구로 바꾸지 않는다. 실행 세션 정책을 기본안으로 기록하고 재생 정책을 분리한다.

## 기존 코드 확인과 후속 설계 범위

2026-09-23 확인: `Assets/MobileUI/Scripts/TabHost.cs`는 버튼으로 `SelectTab`을 호출해 한 화면을 교체한다. `MirrorInput.cs`는 단일 포인터의 클릭·드래그를 씬으로 전달한다. 공통 스와이프 탭 전환과 핀치 줌은 구현되어 있지 않다.

- 공통 스와이프 판정, 전환 중 두 화면 표시, 전환 확정/복귀, 버튼 전환 경로 통합이 필요하다.
- 드래그 콘텐츠와 탭 스와이프의 입력 소유권을 분리하고, 스와이프 시 발굴 등 클릭 오작동을 방지한다.
- 홈 프로필 바에 따른 뷰포트 높이 변화와 기존 탭별 일시정지/복귀 정책을 보존한다.
- Unity Layer 8~31은 탭 카메라 격리용이다. 전시관의 앞뒤 표시 순서는 Sorting Layer/정렬 순서로 처리한다.
- 탭 양 끝 비순환, 떨어진 탭 버튼 선택 시 목적 탭으로 직접 전환은 앞선 기본 설계안이다.
- 모바일용 원본 임포트 해상도·압축과 두 화면 전환 비용을 확인한다.

## 향후 검증 기준

- 상판 외곽 기준 7×7 논리 좌표의 일치, 좌표 왕복 변환, 경계 밖 입력 거부.
- 해상도·시점 배율·플랫폼 표시 변형이 바뀌어도 동일 셀 판정 유지.
- 임시 배치물로 다중 셀 점유와 바닥 접점 깊이 정렬을 검증하되 정령 구현에 의존하지 않기.
- 최초 연출을 재생/생략/완료한 각각의 상태에서 원근감이 독립적으로 작동하기.
- 스와이프 취소·확정·홈 재방문이 최초 연출 완료 상태를 잘못 변경하지 않기.
- 모든 인접 탭의 양방향 전환, 연속 조작, 버튼 이동, 콘텐츠 오클릭 방지, 작업대 일시정지·재개 유지.

이 문서는 요구사항·좌표 계약의 기준 문서다. 구현과 검증 상태는 `exhibition-validation.md`를 참고한다.

## 간단한 하우징과 도깨비 더미 착수 (2026-10-09)

사용자가 전시관 하우징 로직을 먼저 만들고, 이후 돌아다니는 도깨비 더미를 연결하도록 지시했다. 초기 전시물은 1×1로 시작하고 여러 칸 점유를 지원하는 구조를 마련하는 것으로 확정했다. 위의 정령 미포함 기록은 이전 작업 범위이며 이번 도깨비 더미 구현을 제한하지 않는다.

- 첫 조작은 배치 버튼과 셀 터치, 선택 후 빈칸 터치로 이동, 회수·취소 버튼이다. 바닥에는 드래그 핸들러를 두지 않아 탭 스와이프가 우선한다.
- 배치 모델은 셀 앵커·크기·실행 중 ID와 점유를 관리한다. 이동 실패 시 이전 점유를 유지한다. 회전·영구 저장·실제 유물 인벤토리 연계는 후속 범위다.
- 도깨비 더미는 한 마리이며 상하좌우의 빈 인접 셀을 한 칸씩 이동한다. 현재 칸과 목적지를 예약해 이동 도중 전시물이 들어오지 못하게 한다. 별도의 이동 컴포넌트로 후속 이동 로직 고도화를 가능하게 한다.
- 전시물과 도깨비는 플랫폼 콘텐츠 부모 및 바닥 접점 정렬을 공유한다. 최초 등장 완료 후 표시하며 기존 최초 등장·탭 시차 정책을 유지한다.

## 길게 누르기 방향 메뉴 (2026-10-09 후속 변경)

사용자가 전시물을 누르는 동안만 이동·회수·회전 버튼을 주변에 표시하고, 누른 채 해당 버튼 방향으로 스와이프해 기능을 선택하도록 지시했다. 앞선 단순 선택·하단 회수 조작을 이 방식으로 대체한다.

- 기본 길게 누르기 시간은 0.45초다. 위쪽 이동, 왼쪽 아래 회수, 오른쪽 아래 회전을 표시한다. 버튼은 손을 떼거나 입력을 취소하면 닫힌다.
- 길게 누르기 전 이동은 후보를 취소하고 기존 탭 스와이프에 맡긴다. 메뉴가 열리면 해당 제스처를 하우징이 소유하며, 중심의 작은 이동이나 방향 사이의 이동은 기능을 실행하지 않는다.
- 방향을 선택하면 한 번만 실행한다. 메뉴는 계속 누르고 있는 동안 유지하고 실행한 버튼을 강조한다. 회수한 오브젝트의 소멸이 포인터 소유권을 끊지 않도록 입력은 홈 루트에서 처리한다.
- 이동은 목적지 셀을 터치하는 모드로 전환한다. 회수는 즉시 제거한다. 회전은 앵커를 유지하며 90도씩 방향을 바꾸고, 홀수 회전에서 가로·세로 점유 크기를 교환한다. 새 점유가 유효하지 않으면 변경하지 않는다.
- 메뉴 버튼은 독립 클릭 대상이 아닌 방향 스와이프의 시각적 표적이다. 화면 가장자리에서는 메뉴 위치를 보정하고 실제 표시된 버튼 방향으로 선택한다. 기존 배치·취소 버튼은 유지한다.

### 하단 조작 UI 숨김 (2026-10-09 후속 변경)

사용자가 하단 배치 버튼과 안내 문구도 길게 누를 때만 표시하도록 지시했다. 배치·취소·안내를 포함한 하단 패널은 기본적으로 숨기고, 전시물 또는 유효한 상판 셀을 0.45초 누르는 동안만 표시한다. 손을 떼거나 입력을 취소하면 주변 메뉴와 하단 패널을 함께 숨긴다.

평소에 숨긴 배치·취소도 사용할 수 있도록 빈 상판 길게 누르기 → 누른 채 하단 버튼까지 밀기 → 손을 떼고 목적지 터치로 연결한다. 빈 상판에서 길게 누르면 전시물 전용 세 방향 메뉴는 열지 않는다. 버튼을 선택한 이동·배치 상태는 손을 뗀 뒤에도 유지하되 조작 UI는 표시하지 않는다.

### 빈 상판도 주변 메뉴로 통일 (2026-10-09 후속 변경)

사용자가 빈 상판의 배치·취소를 전시물의 주변 메뉴와 비슷한 배치로 바꾸도록 지시했다. 하단 패널을 제거하고 두 메뉴를 `HousingRadialMenu`로 통일한다. 빈 상판은 누른 지점의 왼쪽 배치·오른쪽 취소 두 버튼, 전시물은 기존 이동·회수·회전 세 버튼만 표시한다. 안내도 메뉴 아래에 배치하며 손을 떼면 함께 닫힌다. 공통 방향 판정·화면 경계 보정·한 번만 실행·입력 취소 정책을 유지한다.

현재 더미 전시물은 하나의 배치 ID와 부모 오브젝트 아래에 전시대·유물·방향 표시를 묶은 단위다. 하위 Sprite가 여러 개여도 배치·이동·회수와 깊이 정렬은 이 단위로 함께 처리한다.

### 도감 연결을 위한 전시물 정의 분리 (2026-10-09 후속 변경)

하우징은 도감의 내부 타입 대신 `HousingItemDefinition`의 전시물 종류 ID·점유 크기·표현 프리팹·터치 영역을 사용한다. 종류 ID(`ItemId`)와 배치 인스턴스 ID(`Id`)를 구분하며 이동·회전에도 종류 ID를 유지한다. 초기 전시물은 `Configuration/PrototypeExhibitionItem.asset`에서 1×1로 설정한다. 초기 배치 여부와 위치도 홈 컴포넌트의 직렬화 설정으로 분리했다.

추가 연결 계층은 `ExhibitionHousing.PlacementRequested`를 구독해 도감 선택 화면을 열고, 선택한 정의를 `BeginPlacement(definition)`으로 전달할 수 있다. 구독자가 없을 때만 기존 임시 전시물을 기본으로 사용한다. `PlacementAdded`와 `PlacementRemoved`는 배치 정보와 종류 ID를 전달한다. 해금·보유 수량·소유권 검사·저장은 아직 구현하지 않았으며 연결 계층에서 별도로 설계해야 한다.

실제 아트는 정의의 `VisualPrefab`으로 교체한다. 프리팹은 바닥 접점을 원점으로 하는 표현용 자식이며 하우징의 부모가 셀 위치·레이어·깊이 정렬·터치를 관리한다. 표현 프리팹에는 독립 Camera·EventSystem·AudioListener를 두지 않는다. 방향별 표현이 필요하면 자식 컴포넌트에서 `IHousingRotationView.SetFacing`을 구현한다. 프리팹이 없는 현재 정의는 기존 더미 표현을 사용한다. 도감의 구체적인 데이터 구조를 하우징에 직접 참조하지 않는다.
